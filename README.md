# symbolize

Live: https://chikirao.github.io/symbolize/

Генератор эффекта **symbol / shape halftone portrait**: изображение превращается в мозаику из
мелких символов, размер / цвет / поворот / плотность которых зависят от яркости, альфа-канала,
маски и градиента исходной картинки.

Источником может быть не только фото: видео (mp4 / webm / mov) и анимированные GIF / WebP
раскладываются на кадры, и эффект считается для каждого кадра отдельно. Плюс таймлайн с
ключевыми кадрами на сами параметры — так оживает и обычная фотография. Результат
экспортируется в GIF, WebM, APNG или последовательность PNG.

Всё работает локально в браузере. Файлы читаются через `FileReader`, рисуются в `<canvas>` и
никуда не отправляются — ни бэкенда, ни аналитики, ни внешних API.

Интерфейс — монохромный ASCII / terminal-стиль (Ubuntu Mono), сам результат — любых цветов.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Дальше открыть `http://localhost:5173/symbolize/`.

Production-сборка:

```bash
npm run build
```

Проверка типов без сборки:

```bash
npm run typecheck
```

Требования: Node 18+, современный Chromium / Firefox / Safari. Интерфейс адаптирован для desktop,
телефонов и touch-планшетов. При ширине меньше 900 px (а на touch-устройствах — до 1199 px)
включается отдельный мобильный workspace.

При первом запуске загружается встроенное демо-изображение (`src/assets/demo-bunny.jpg`, локальный ассет, без сети), поэтому эффект виден сразу. Если картинка почему-то не декодируется, используется запасной процедурный силуэт.

Своё изображение можно дать четырьмя способами:

* кнопка `[ LOAD ]` или меню `FILE → LOAD IMAGE`;
* drag & drop в любое место окна;
* **Ctrl+V в любом месте страницы** — картинка из буфера обмена вставляется сразу
  (скриншот, копия из Photoshop / браузера / Figma);
* кнопка `[ PASTE ]` — читает буфер через `navigator.clipboard.read()`; если браузер это
  запрещает, покажет подсказку нажать Ctrl+V.

Форматы: всё, что браузер умеет декодировать (PNG / JPEG / WEBP / GIF / BMP / AVIF).
SVG как источник не принимается — он зарезервирован под пользовательские символы.

Вставка не перехватывает Ctrl+V в текстовых полях: если в буфере есть текст и фокус стоит в
поле ввода (например `ADD UNICODE`), поле получает текст как обычно. Картинка перехватывается
только когда текста в буфере нет или фокус вне поля.

### Управление на телефоне

Canvas занимает свободную часть экрана и остаётся видимым во время работы. Внизу находится dock
из пяти разделов: `IMAGE`, `SYMBOLS`, `PRESETS`, `PARAMS`, `EXPORT`. Раздел открывается как
прокручиваемая панель поверх нижней части canvas; повторный тап по активной кнопке или `[ CLOSE ]`
закрывает её.

* один палец двигает изображение;
* два пальца масштабируют относительно центра жеста;
* двойной тап делает Fit to screen;
* кнопки `[-]`, `[FIT]`, `[+]`, `[A/B]` дают точное управление без жестов;
* `[LOAD]`, `[RND]`, `[FIT]`, `[ORIG]` всегда доступны в верхней строке;
* панели не перетягивают canvas и имеют собственный вертикальный скролл;
* touch-targets контролов увеличены, учтены safe-area и экранная клавиатура.

### Pipeline

```
loadImage()          файл -> canvas (локально)
buildSourceMaps()    один getImageData -> lum / alpha / rgb в typed arrays
buildGrid()          массив ячеек в координатах ИСХОДНОГО изображения
calculateElements()  на ячейку: sampling -> levels -> mask -> threshold ->
                     edges -> density -> symbol -> size -> rotation ->
                     opacity -> color, результат в structure-of-arrays
drawElements()       отрисовка из типизированных массивов
renderComposite()    background -> silhouette -> original (clip) -> pattern
```

`getImageData` вызывается **один раз** на загрузку изображения. Дальше сэмплинг идёт из
`Float32Array` / `Uint8ClampedArray`. Элементы хранятся в SoA-буфере
(`x`, `y`, `size`, `rot`, `a`, `r`, `g`, `b`, `sym`), без объекта на символ.

Ключевая деталь: **сетка строится в координатах исходного изображения**, а разрешение задаётся
только матрицей `ctx.setTransform`. Поэтому превью и экспорт — одна и та же композиция в разном
масштабе.

## Алгоритм

Для каждой ячейки сетки:

1. **Сэмплинг.** Берётся не один центральный пиксель, а стратифицированная сетка 1×1…4×4 отсчётов
   внутри площади ячейки; усредняются luminance, alpha и RGB.
   `L = 0.2126·R + 0.7152·G + 0.0722·B`
2. **Source mode.** `luminance`, `alpha` или `luminance × alpha`.
3. **Levels.** black/white point → brightness → contrast → gamma → invert.
4. **Mask.** `alpha` / `luminance` / комбинация / выделение по цвету, затем threshold + feather +
   invert. Ячейки вне маски отбрасываются. Полностью прозрачные пиксели пропускаются всегда.
5. **Threshold.** полоса `[min, max]` с мягким краем (`soft`); значение `0…1` умножает размер и
   прозрачность, а не режет бинарно. `invert` переворачивает правило.
6. **Edges.** Sobel `edge = sqrt(gx² + gy²)`, максимум по радиусу `thickness`.
   Режимы: `inside` (только внутренность), `edges` (только контур), `both` (контур усиливается
   параметром `boost`).
7. **Density.** `p = density × (1 | 1 − L | L)`, дополнительно усиливается на краях.
   Ячейка отрисовывается, если `random() ≤ p`.
8. **Symbol.** `random` по весам, `luminance` (диапазоны яркости → разные фигуры), `sequential`,
   `noise` (value noise). Пул собирается из 73 встроенных фигур, своих Unicode-глифов и
   загруженных SVG/PNG.
9. **Size.** `scale = pow(1 − L, γ)` для dark→large, `pow(L, γ)` для light→large;
   `size = lerp(min, max, scale) × cellSize`. Плюс jitter и опциональный clamp по ячейке.
10. **Rotation.** `fixed` / `random` / `luminance` / `gradient`
    (`atan2(gy, gx)`, вдоль или перпендикулярно контуру) + jitter.
11. **Color.** `solid`, `ORIGINAL AVG` (средний RGB ячейки), `ORIGINAL PIXELS` (исходное
    изображение просвечивает сквозь форму символа), градиент по яркости / X / Y / радиусу,
    `ORIGINAL MAIN` (доминирующий цвет фрагмента), затем hue shift, saturation, brightness, jitter.
12. **Opacity.** `constant` / от яркости / от альфы, с гаммой и jitter.

### Adaptive grid (квадродерево)

Режим `GRID → ADAPTIVE` даёт разный размер символов в зависимости от того, насколько «занят»
участок картинки — как в Array Machine.

Изображение режется на квадраты со стороной `MAX CELL`. Для каждого квадрата считается локальный
контраст: максимальный разброс яркости, альфы и любого из RGB-каналов по стратифицированной
выборке точек. Если разброс больше `DETAIL`, квадрат делится на четыре, и проверка повторяется —
пока не упрётся в `MIN CELL` или `MAX DEPTH`.

Итог: ровная заливка остаётся одной большой ячейкой и получает один крупный символ, а контуры,
границы цветов и мелкие детали дробятся и заполняются множеством мелких символов.

Размер символа считается от **собственной** стороны ячейки (`Cell.unit`), а не от глобального
`cellSize` — иначе дробление не влияло бы на масштаб фигур. Полностью прозрачные квадраты не
дробятся: их всё равно отбросит маска.

Для чистого квадродерева стоит поставить `SIZE → CONSTANT`, иначе поверх наложится ещё и
зависимость размера от яркости (что тоже бывает красиво).

### Детерминизм

Все случайные значения берутся из seeded PRNG (mulberry32). Генератор создаётся **на ячейку** от
хэша `(seed, col, row)`, и значения вытягиваются в фиксированном порядке — поэтому включение любой
опции не «перетасовывает» остальную картинку. Одинаковый seed + одинаковые настройки всегда дают
идентичный результат; `[ RANDOMIZE ]` меняет seed.

## Символы

**Встроенная библиотека — 73 фигуры** в пяти группах.

Три нейтральные базовые группы (BASIC / DIRECTIONAL / GRAPHIC): круги, квадраты, треугольники,
ромбы, шестиугольники, капсулы, стрелки (линейные, блочные, двойные, шевроны, каретки), кресты,
кольца, мишени, прицелы, звёзды, растры точек, штриховки, волны, уголки.

И два **вайб-набора** — каждый со своим характером:

* `SOFT` (ROUND / ORGANIC) — блоб, сквиркл (заливка и контур), пончик, линза, четверть круга,
  полумесяц, скруглённый ромб, скруглённый треугольник, четырёхлистник, пилюля, лепесток,
  пузыри, рябь, мягкая волна, толстая дуга.
* `SHARP` (ANGULAR / SPIKED) — лезвие, шип, осколок, молния, кайт, шипастая звезда (4 и 8 лучей),
  бритва, клин, трапеция, острая стрелка, тяжёлый шеврон, диагональные полосы, пила.

Всё это Canvas-геометрия, а не шрифт — вид не зависит от системы.

Панель `ELEMENTS` слева — палитра плиток: клик включает фигуру, включённые подсвечены рамкой,
цифра в углу показывает вес. `[ALL]` / `[NONE]` / `[MIX]` (случайный набор из 3–5 фигур).
Строка `SET` под ними загружает вайб-набор одним кликом: включается стартовая подборка фигур
набора и его толщина обводки. У каждой группы справа есть `ADD` / `REMOVE` — добавить всю группу
к текущему выбору или убрать её целиком (последний символ не отключается).
Ниже — список `ACTIVE` с весами: вес задаёт вероятность фигуры в режиме `RANDOM`.

**Готовые наборы глифов (`GLYPH PACKS`).** Девять подборок Unicode; каждая показана строкой с
её реальным содержимым (в собственном шрифте подборки) и счётчиком, клик по строке добавляет её:
`BLOCKS` (▓▒░ и полублоки), `GEOMETRIC` (круги, доли круга, треугольники, шестиугольники),
`ARROWS`, `STARS`, `TECH` (⌘ ⎋ ⌬ и прочая техника), `LINES` (псевдографика рамок и диагоналей),
`MATH`, `KANA` (катакана), `GLYPHIC` (редкие геометрические знаки). Каждая подборка добавляется
как отдельные символы со своими весами — дальше их можно выключать и смешивать с векторными.

**Свои Unicode-символы.** В секции `ADD UNICODE` вводится строка любых символов —
`★✦→▲✕◆`, стрелки, японские знаки, значки, эмодзи. Каждый символ становится отдельной фигурой
в пуле, с собственным весом и включением. Можно выбрать шрифт (Ubuntu Mono / monospace / sans /
serif / symbols / emoji) и жирность. Глифы рисуются через `fillText`, а не растеризуются, поэтому
остаются чёткими на любом разрешении экспорта; они центрируются по реальному ink box, а не по
baseline, и масштабируются под размер ячейки.

Оговорки: вид глифа зависит от шрифтов, установленных у зрителя, а цветные эмодзи рисуются
своими цветами и не подхватывают градиент. Именно поэтому основная библиотека — векторная.

**Свои SVG / PNG** — секция `ADD SVG / PNG` (drag & drop). Для SVG по умолчанию включён `TINT`:
монохромная картинка перекрашивается настройками цвета.

## Маска и выделение

Маска решает, **где** вообще появляются символы. Ячейка, чьё значение маски равно нулю,
пропускается целиком; на растушёванном крае символы уменьшаются и бледнеют.

`MASK SOURCE` — что считать маской:

* `SOURCE ALPHA` — прозрачность исходника. Для вырезанного PNG это готовый силуэт.
* `LUMINANCE` — яркость: например, только тёмные области.
* `LUM x ALPHA` — комбинация.
* `COLOR RANGE` — выделение по цвету (см. ниже).

Дальше значение проходит `MASK THRESHOLD` (порог), `MASK FEATHER` (мягкость края) и
`INVERT MASK` (инверсия — выделенное наоборот выбрасывается). Отдельно `SHOW FILL` заливает
область маски сплошным цветом под узором — тот самый силуэт.

Превью маски всегда видно в панели `SOURCE` слева: белое = символы разрешены.

### Выделение по цвету

`MASK SOURCE → COLOR RANGE`, дальше `[ PICK COLOR ]` и клик по канвасу — курсор становится
крестом, клик берёт цвет (усреднение 3×3, чтобы не поймать шумный пиксель). Кликов можно сделать
несколько: цвета накапливаются, выделяется объединение. Каждый цвет можно поправить вручную
через свотч или удалить.

* `TOLERANCE` — насколько далеко пиксель может отстоять от выбранного цвета. Расстояние считается
  по redmean-метрике, а не по «сырому» RGB: она заметно ближе к восприятию, поэтому даже при
  большом допуске красный не начинает захватывать синий.
* `CONTIGUOUS (WAND)` — волшебная палочка: остаётся только область, физически связанная с точкой
  клика (заливка по строкам от seed-точки). Выключено — берутся все совпадающие пиксели по всей
  картинке.
* `INVERT MASK` превращает выделение в вычитание: символы лягут везде, **кроме** выбранного цвета.

Поле выделения считается на карте анализа один раз и кэшируется по подписи (цвета + допуск +
режим + точки), так что таскание других слайдеров его не пересчитывает.

### Узор поверх оригинала

Маска сама по себе только выбирает область. Чтобы получить «оригинал на фоне, а выбранный цвет
превращён в символы поверх него», в секции `BACKGROUND / LAYERS` включается `SHOW ORIGINAL`, и
дальше работает `ORIGINAL CLIP`:

* `FULL` — фотография целиком под узором.
* `CUT MASK OUT` — из фотографии вырезается область маски, и в дыру видно то, что нарисовал слой
  фона: `BACKGROUND` transparent / white / black / custom. То есть выбранный цвет «заменяется» на
  фоновый, а сверху ложатся символы.
* `MASK ONLY` — от фотографии остаётся только выделенная область, всё остальное уходит в фон.

Порядок слоёв: `BACKGROUND → SILHOUETTE → ORIGINAL → PATTERN`, поэтому символы всегда сверху.
Вырезание делается стенсилом того же поля маски (`destination-out` / `destination-in`), а поле
считается один раз и кэшируется — им же пользуется силуэт.

**Чего здесь нет:** семантического выделения («выдели человека»). Для этого нужна ML-модель, а это
и вес в мегабайтах, и отход от принципа «всё локально, без сторонних сервисов». Практически
задачу закрывают три вещи: альфа-канал (если картинка уже вырезана), выбор по цвету и волшебная
палочка. На плоской графике, логотипах и рендерах этого хватает; на фотографии со сложным фоном —
нет, там честнее вырезать объект заранее и принести PNG с прозрачностью.

## Цвет из исходника

Три режима берут цвет из самой картинки:

* `ORIGINAL AVG` — усреднённый RGB ячейки. Один плоский цвет на символ, мягкие переходы, но на
  границе двух контрастных цветов даёт смесь: красный + синий = грязно-фиолетовый.
* `ORIGINAL MAIN` — **доминирующий** цвет фрагмента, тоже один плоский цвет на символ. Отсчёты
  внутри ячейки раскладываются в гистограмму (4 бита на канал, 4096 корзин), берётся самая
  populous корзина и усредняется уже внутри неё. На той же границе даст чистый красный или
  чистый синий, а не смесь. Прозрачные отсчёты в гистограмму не попадают.
* `ORIGINAL PIXELS` — символы работают как трафарет: сначала весь узор рисуется в альфа-слой,
  затем сквозь него композитится исходное изображение (`source-in`). Внутри крупного символа
  видно реальное содержимое фрагмента со всеми переходами.

В режиме `ORIGINAL PIXELS` ползунки hue / saturation / brightness не применяются — цвет берётся
из пикселей как есть. Прозрачность символов при этом сохраняется. `AVG` и `MAIN` их учитывают.

## Анимация

Панель `TIMELINE` внизу (на телефоне — раздел `ANIM` в доке). Она нужна для двух разных вещей,
которые делят один таймлайн.

### Видео и GIF как источник

Перетащите mp4 / webm / mov или анимированный GIF / WebP — файл разложится на кадры, и каждый
кадр пройдёт через тот же самый конвейер, что и фотография: цвет, маска, символы, всё.

* видео сэмплируется перемоткой скрытого `<video>` с выбранной частотой (по умолчанию 12 fps);
* GIF / WebP / AVIF декодируются через `ImageDecoder` (WebCodecs), а там, где его нет, работает
  свой GIF-ридер — с LZW, чересстрочностью и disposal;
* кадры хранятся как `ImageBitmap` с ограничением по длинной стороне (по умолчанию 800 px).
  Сетка живёт в координатах источника, а символы векторные, поэтому кадр 800 px спокойно
  экспортируется в 3200 px — но 240 полноразмерных кадров в память не влезли бы;
* таймлайн — главные часы. Источник короче таймлайна повторяется, длиннее — обрезается.

### Ключевые кадры на параметрах

У каждого анимируемого параметра справа появился маркер: `[ ]` — трека нет, `[.]` — трек есть,
но на этом кадре ключа нет, `[*]` — ключ здесь. Клик ставит или снимает ключ.

* если у параметра есть трек, слайдер показывает значение **на текущем кадре** и пишет ключи;
* если трека нет, слайдер меняет базовое значение — пока не включён `AUTO KEY`;
* easing на ключ: `LINEAR` / `EASE IN` / `EASE OUT` / `EASE IN-OUT` / `HOLD`;
* переключатели и режимы (enum) анимируются только через `HOLD` — интерполировать enum нельзя;
* ключи двигаются мышью прямо по строке трека;
* `SAVE ANIM` / `LOAD ANIM` — таймлайн в JSON, отдельно от пресетов.

Треки живут в **отдельном сторе** и никогда не пишутся обратно в настройки: playhead двигается
до 60 раз в секунду, и если бы это шло через store настроек, перерисовывались бы все панели.

### Зоны

Самое интересное здесь — не шторки на весь кадр, а выделенная область, которая живёт отдельно от
остального изображения.

1. Включите маску и ткните пипеткой в нужный цвет (`MASK` → режим `COLOR RANGE`, инструмент
   `PICK` на канвасе).
2. Переведите `MASK MODE` в `SELECT`. В этом режиме маска ничего не прячет — она только помечает
   зону. `GATE` — прежнее поведение, когда всё снаружи удаляется.
3. Откройте секцию `ZONE` и крутите: размер, прозрачность, плотность, поворот, hue, насыщенность,
   прокрутка градиента, смещение. Всё это применяется **только внутри выделения** и взвешивается
   тем же мягким полем, так что растушёванный пик даёт растушёванный эффект.

`INVERT ZONE` переворачивает: параметры применяются ко всему, **кроме** зоны — отсюда приём
«цветной объект на обесцвеченном фоне».

Отдельный подраздел `OUTLINE` работает не с самой зоной, а с её **границей**: толщина в пикселях,
размер, прозрачность и hue символов, попавших на контур. `OUTLINE ONLY` выбрасывает всё, кроме
контура — получается объект, обведённый символами. Граница считается Sobel-проходом по полю маски,
то есть это край именно того, что вы выделили, а не край яркости.

Все параметры зоны анимируются, и на них есть готовые пресеты: `ZONE PULSE`, `ZONE HUE`,
`ZONE RIPPLE`, `ZONE OUTLINE`, `ZONE SPOT`.

На видео выделение считается **для каждого кадра заново**, поэтому зона едет за объектом сама:
выбрали оранжевый мяч — зона следует за мячом по всему клипу. Подготовка кадра вместе с
выделением стоит доли миллисекунды на кадр, пока клип помещается в кэш (256 МБ, то есть около
35 кадров в 800×600 или больше сотни в 320×240).

Если цвет объекта по ходу клипа уплывает — освещение поменялось, объект повернулся — не ждите,
что толеранс подстроится сам: поставьте два ключа на `MASK TOLERANCE`. Это видно и обратимо, в
отличие от автоматики.

### Параметры, сделанные специально для анимации

* `REVEAL` — независимая шторка после маски: linear / radial / luminance / noise. Анимация
  `AMOUNT` от 0 к 1 — это и есть интро (а от 1 к 0 — аутро).
* `MOTION` — смещение символов волной / от центра / шумом плюс `SWIRL`. Применяется только к
  позиции вывода: ячейка по-прежнему читает источник там, где стоит, поэтому картинка остаётся
  на месте, а символы едут поверх неё.
* `DENSITY SOFTNESS` — то же стабильное случайное число, но как расстояние до порога, а не
  «да / нет»: ячейки проявляются плавно, а не выскакивают.
* `NOISE PHASE` и `MOTION PHASE` ходят по кругу в поле шума, поэтому фаза 0 и фаза 1 дают
  одинаковые значения и цикл не дёргается на стыке.
* `GRADIENT OFFSET` прокручивает LUT градиента — бегущий градиент без правки самих стопов.
* Seed по умолчанию не анимируется специально: менять его каждый кадр = телевизионный снег.

### Транспорт

```
[|<] [<] [PLAY] [>] [>|]   FRAME 024/047   FPS 12   LEN 48   LOOP   AUTO KEY
```

Превью играет в реальном времени и **пропускает кадры**, если рендер не успевает: целевой кадр
считается как `floor(прошло * fps)`, поэтому длина ролика не «плывёт». Во время проигрывания
качество превью — draft. Экспорт кадры не пропускает никогда.

## Экспорт

`EXPORT` в правой панели (или меню `EXPORT` для быстрого PNG). Переключатель `OUTPUT` наверху
выбирает между одиночной картинкой и анимацией; при загрузке видео он сам встаёт в `ANIMATION`.

### Одиночный кадр

* форматы PNG / JPEG / WEBP, для PNG сохраняется прозрачность;
* разрешение: Original / 2× / 4× / Custom (с блокировкой пропорций);
* изображение **перерисовывается целиком в экспортном разрешении** — превью-канвас не масштабируется;
* все пространственные параметры (cell size, offsets, размеры символов) масштабируются
  пропорционально, композиция совпадает с превью;
* рендер идёт чанками с прогрессом, вкладка не «замерзает»;
* `[ DOWNLOAD ]` — файл `symbolize-YYYY-MM-DD-HHMM.png`;
* `[ COPY PNG ]` — в буфер обмена, если браузер поддерживает `ClipboardItem`.

Ограничения экспорта: максимум 8192 px по стороне и ~48 Мп (иначе canvas не выделяется).
При превышении размер клампится, о чём панель пишет `(CLAMPED)`.

JPEG и WEBP не имеют альфы: прозрачный фон в них станет чёрным — для прозрачности нужен PNG.

### Анимация

| Формат | Когда брать | Чем платите |
| --- | --- | --- |
| `GIF` | открывается везде, постится куда угодно | 256 цветов на кадр, альфа только 1-битная |
| `WEBM` | лучший размер и качество, длинные ролики | нет альфы, нужен WebCodecs (Chrome / Edge) |
| `APNG` | честный цвет и полная альфа | файлы заметно тяжелее |
| `PNG SEQ` | дальше в After Effects / ffmpeg | ZIP на десятки мегабайт |

Всё кодируется в браузере, без библиотек: свой GIF-энкодер (медианный срез палитры,
Флойд-Стейнберг, LZW и покадровая разница — в кадр пишется только изменившийся прямоугольник),
APNG поверх `CompressionStream` с адаптивной фильтрацией строк, WebM через `VideoEncoder`
плюс маленький EBML-муксер.

Настройки: разрешение, fps, диапазон кадров, а для GIF ещё размер палитры, дизеринг и альфа.
`! CANCEL` останавливает экспорт в любой момент. Ограничения — 600 кадров и ~240 Мп суммарно;
панель заранее предупреждает, если задание тяжёлое.

Задержка кадров копится в сотых долях секунды, а не округляется на каждом кадре: 12 fps
остаётся 12 fps, а не уезжает на 4 % за ролик.

## Производительность

* `getImageData` — один раз на изображение; карты анализа ограничены 1800 px по длинной стороне.
* Карта краёв (Sobel) считается лениво и кэшируется на карту источника.
* Во время перетаскивания слайдера превью рендерится в low-разрешении (`DRAFT` в статус-баре),
  после отпускания — в выбранном качестве (`LOW` / `MEDIUM` / `HIGH` в меню `VIEW`).
* Сетки больше ~26 000 ячеек рендерятся асинхронно чанками с прогресс-баром.
* Ориентир на обычном железе: изображение 1500×1500, cell size 16–20 → ~7 000 символов,
  десятки миллисекунд на кадр. Cell size 6 на том же изображении — это уже ~64 000 символов,
  сотни миллисекунд: это осознанно экстремальная настройка.

## Ограничения

* Рендер — Canvas 2D в основном потоке. Web Worker не используется: узкое место — растеризация
  путей, которую воркер без OffscreenCanvas не ускорит. Движок написан как набор чистых функций,
  так что перенос в worker / WebGL не потребует переписывать UI.
* Превью рендерится в разрешении, ограниченном бюджетом качества, а не в разрешении зума:
  при большом увеличении очень крупного изображения картинка будет мягче, чем экспорт.
  Свыше 300 % включается `image-rendering: pixelated`, чтобы видеть сетку.
* Исходное изображение уменьшается до 6000 px по длинной стороне.
* Blend modes ограничены теми, что поддерживает `globalCompositeOperation`.
* Интерполяция градиента — в sRGB (не в linear/OKLab).
* `ORIGINAL PIXELS` игнорирует hue / saturation / brightness и требует отдельного offscreen-слоя,
  то есть при экспорте 4× держит в памяти вторую копию холста.
* Пользовательские SVG растеризуются в 256 px и перекрашиваются целиком (`TINT`), поэтому
  многоцветные SVG лучше использовать без перекраски.
* Unicode-глифы зависят от шрифтов на машине зрителя; цветные эмодзи игнорируют настройки цвета.
* Пресеты пользователя хранятся в `localStorage` — они привязаны к браузеру и профилю.
* Анимации (scramble, ASCII-глитч, boot) отключаются при `prefers-reduced-motion: reduce`.

## Вход в приложение

Загрузка состоит из трёх шагов и живёт наполовину в `index.html` (до React), наполовину
в `src/ui/intro.ts`:

1. **Boot-лог.** Слева печатаются строки `> loading renderer` … `> ready`, рядом бежит
   ASCII-полоса прогресса. Любая клавиша или клик пропускает лог и сразу открывает гейт.
2. **Гейт.** По центру страницы появляется `PRESS ANY KEY TO CONTINUE` (на тач-устройствах —
   `TAP TO CONTINUE`) с мигающим курсором; лог остаётся слева с заполненной полосой, а на
   узких экранах (< 900 px) скрывается, чтобы не мешать центру. Слушатель нажатия ставится сразу, а не после
   анимации, чтобы нажатие не потерялось. Нажатие любой клавиши, клик, тач или колесо
   растворяют строку в шум и дают залп ASCII-помех на весь экран.
3. **Волна.** Интерфейс уже смонтирован, но скрыт (`.intro-armed`). `runIntro()` ведёт
   фронт сверху вниз за ~1.5 с. Появление интерфейса отстаёт от фронта на `REVEAL_LAG`
   (210 px): сначала проходит полоса ASCII-шума, и только потом, в её следе, зажигаются
   панели — иначе движение не успеваешь заметить. Граница показа почти жёсткая (14 px), так
   что она читается как прочерченная линия, а не как серый градиент. Каждая текстовая нода
   собирается из случайных глифов за этой линией. Клик или клавиша в процессе — мгновенный
   пропуск.

Детали реализации:

* Время копится покадрово с ограничением `min(48 ms, dt)`: во вкладке в фоне `requestAnimationFrame`
  останавливается, и без этого волна «прыгнула» бы в конец при возвращении на вкладку.
* Позиции строк (`getBoundingClientRect`) читаются все разом до первой записи — один layout
  на весь проход.
* Ни один кадр не проходит через React: меняются `nodeValue` текстовых нод и одна строка маски.
* `VIEW > REPLAY INTRO` проигрывает вход заново.
* При `prefers-reduced-motion: reduce` волна и скрамбл выключены, гейт остаётся.
* Страховки: если приложение не поднялось за 7 с, гейт показывается всё равно; если boot-экран
  исчез, а волну никто не запустил, `App` запускает её сам.
